### การอัปเดต Windows จาก V7.4

1. **สำรองโฟลเดอร์โปรแกรมทั้งชุด และปิดหน้าต่าง CMD** ที่กำลังรัน V7.4
2. ดาวน์โหลดแพตช์ `Affiliate_Auto_Studio_Update_0.7.4_to_0.7.5.zip` จากที่เดียวกับชุดโปรแกรมเท่านั้น
3. ย้ายแพตช์ไป `updates/inbox/` ภายในโฟลเดอร์ **V7.4 ตัวเดิม**
4. ดับเบิลคลิก `update_windows.bat` โปรแกรมจะตรวจแหล่งเวอร์ชัน/ไฟล์ก่อนเขียนและเก็บข้อมูลเดิมไว้
5. เปิด `run_windows.bat` แล้วเช็ก `/api/system/version` ว่าเป็น `0.7.5`

**คำเตือน:** ตัวอัปเดต ZIP ยังไม่ตรวจลายเซ็นผู้เผยแพร่ อย่าใช้แพตช์ที่ได้จากคนอื่น/ลิงก์ไม่ทราบแหล่งที่มา

## เตรียมเปิด Beta ออนไลน์สำหรับ 100 บัญชี

**ต้องมี:** Linux VPS + โดเมน + DNS ชี้ไป IP ของ VPS + Docker/Compose + เปิดพอร์ต 80/443 + สำรองข้อมูล + ตรวจการตั้งค่า TLS และความปลอดภัย

1. คัดลอกโฟลเดอร์โปรเจกต์นี้ไป VPS Linux (อย่าส่ง `data`, `.env`, คีย์หรือฐานข้อมูลจริงให้คนอื่น)
2. สร้าง `.env` โดยคัดลอก `.env.server.example` และกรอก `DOMAIN`, `APP_MASTER_KEY` (Fernet key) และ `BETA_INVITE_CODE` ที่คาดเดายาก
3. ชี้ DNS A record โดเมนไป IP VPS; เปิดพอร์ต 80/443 และติดตั้ง Docker Compose
4. รัน `docker compose up -d --build`
5. ตรวจ `docker compose ps` และ `docker compose logs --tail=100 app caddy`
6. เข้า `https://โดเมนของคุณ` ทดสอบสมัคร/ล็อกอิน, Donate, โหวต, ข้อมูลบัญชีแยกกันด้วยบัญชีทดสอบ 2 บัญชี
7. สมัครบัญชีเจ้าของเว็บแล้วตั้งเป็น Admin บน VPS ด้วยคำสั่ง `docker compose exec app python promote_admin.py owner@example.com` โดยเปลี่ยนเป็นอีเมลที่สมัครจริง และล็อกอินใหม่
8. แจกเฉพาะลิงก์เว็บและรหัสเชิญให้ผู้ทดสอบ ไม่ต้องให้ผู้ใช้ลง Python หรือ ZIP

**สำคัญ:** รูปแบบ Public จะ **ปิด Studio V6 รุ่นเดิม** เพื่อป้องกันการแชร์ข้อมูลระหว่างบัญชี; สมาชิก Beta ใช้ Studio ส่วนตัวรุ่นใหม่แทน

### ความปลอดภัยและการปฏิบัติการที่ต้องทำก่อนเปิดจริง

- HTTPS/TLS ที่ทำงานจริง, อีเมลผู้ดูแล, รหัสเชิญ Beta ไม่เผยแพร่สาธารณะ
- ตั้ง Cloudflare/WAF และ rate limits เพิ่ม โดยเฉพาะ `/api/register` `/api/login` และการเขียนความคิดเห็น เพราะ rate limit ในแอปเป็นเพียงชั้นเริ่มต้น
- สำรอง `beta_data` และ `APP_MASTER_KEY` **แยกกันอย่างปลอดภัย** ทุกวัน ทดลองกู้คืนก่อนเปิดจริง; หากทำ master key หาย จะถอดรหัส API keys ที่สมาชิกเก็บไม่ได้
- ตั้งระบบแจ้งเตือน, ตรวจประสิทธิภาพ, แผนรีสตาร์ท, ความปลอดภัยของเซิร์ฟเวอร์และหลักเกณฑ์ความเป็นส่วนตัว
- SQLite WAL ใช้กับ 100 บัญชีและงานเขียนเบา ๆ ได้ในการทดลองบน single instance แต่ไม่ควรอ้างว่ารองรับผู้ใช้พร้อมกัน 100 คนจากจำนวน account; อย่ารันหลาย replica กับ SQLite ไฟล์เดียว
- ยังไม่ควรชวนผู้ใช้เชื่อม API keys จริงจนผ่าน security review ของระบบ Production
